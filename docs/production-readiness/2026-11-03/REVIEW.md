# RoomSmith static review

## Scope and verdict

**Prototype implementation**, not a finished Fire OS product. Pinned public repository: [`knarayanareddy/roomsmith`](https://github.com/knarayanareddy/roomsmith/tree/7036277be3f81dad1c3dafa3cc29c2ce04cf9807), SHA `7036277be3f81dad1c3dafa3cc29c2ce04cf9807`. The snapshot's tree contains 110 paths and is not truncated; that is not evidence that all paths were reviewed. Runtime, installation, build, tests, deployment, hardware and accessibility checks: **NOT RUN**. Confidence is high for quoted control flow, low for end-to-end behavior and exploitability.

The main release blocker is a TV signaling handshake that treats possession of a session ID as authentication. The development configuration also exposes services and Redis beyond loopback. These are source observations, not a claim of a demonstrated intrusion. The project's own [README:3–7](https://github.com/knarayanareddy/roomsmith/blob/7036277be3f81dad1c3dafa3cc29c2ce04cf9807/README.md#L3-L7) says Fire OS and companion applications are not implemented and places puzzle completion in the deterministic engine. The [README:43–47](https://github.com/knarayanareddy/roomsmith/blob/7036277be3f81dad1c3dafa3cc29c2ce04cf9807/README.md#L43-L47) explicitly says the fixture does not prove physical playability. See [remediation plan](REMEDIATION_PLAN.md).

## Architecture and product boundary

The root package's [`dev` script](https://github.com/knarayanareddy/roomsmith/blob/7036277be3f81dad1c3dafa3cc29c2ce04cf9807/package.json#L10-L18) runs observation and Kotlin fixtures. Separately, [Compose:17–32](https://github.com/knarayanareddy/roomsmith/blob/7036277be3f81dad1c3dafa3cc29c2ce04cf9807/docker-compose.yml#L17-L32) starts the standalone signaling server, which creates a demo session and observation ingress ([server:15–45](https://github.com/knarayanareddy/roomsmith/blob/7036277be3f81dad1c3dafa3cc29c2ce04cf9807/services/signaling/src/server.ts#L15-L45)). The separate Fire TV web simulator serves `simulator.getState()` ([server:98–102](https://github.com/knarayanareddy/roomsmith/blob/7036277be3f81dad1c3dafa3cc29c2ce04cf9807/apps/firetv/src/server.ts#L98-L102)); the companion test server serves synthetic cards ([server:52–55](https://github.com/knarayanareddy/roomsmith/blob/7036277be3f81dad1c3dafa3cc29c2ce04cf9807/apps/companion/src/server.ts#L52-L55)). Neither proves native-app integration. The director validates coarse context, invokes an injectable gateway and validates authored output; the actual engine wiring and remote provider were not traced. External platform, device, signaling, content and AWS dependencies remain owner-controlled or unimplemented per README.

## Findings ledger

**RS-01 — High, confirmed static: TV identity is not authenticated.** The [signaling handshake:346–385](https://github.com/knarayanareddy/roomsmith/blob/7036277be3f81dad1c3dafa3cc29c2ce04cf9807/services/signaling/src/websocket-signaling-server.ts#L346-L385) checks `getSession`, assigns `group.tv = peer`, then replies `authenticated: true`; unlike the [companion path:388–441](https://github.com/knarayanareddy/roomsmith/blob/7036277be3f81dad1c3dafa3cc29c2ce04cf9807/services/signaling/src/websocket-signaling-server.ts#L388-L441), it checks no TV credential. Subsequent routing selects `group?.tv` ([routing:533–549](https://github.com/knarayanareddy/roomsmith/blob/7036277be3f81dad1c3dafa3cc29c2ce04cf9807/services/signaling/src/websocket-signaling-server.ts#L533-L549)). Someone with network access and a valid session ID can register as TV and replace the routing target; exact downstream exposure remains untested. The demo logs session ID and pairing code ([server:61–65](https://github.com/knarayanareddy/roomsmith/blob/7036277be3f81dad1c3dafa3cc29c2ce04cf9807/services/signaling/src/server.ts#L61-L65)). Require a session-bound TV credential and test replacement/revocation through real sockets.

**RS-02 — High for deployment, confirmed static configuration: development services are network exposed.** [Compose:4–9](https://github.com/knarayanareddy/roomsmith/blob/7036277be3f81dad1c3dafa3cc29c2ce04cf9807/docker-compose.yml#L4-L9) publishes Redis port `6379:6379` and specifies no password in the shown command; [Compose:23–32](https://github.com/knarayanareddy/roomsmith/blob/7036277be3f81dad1c3dafa3cc29c2ce04cf9807/docker-compose.yml#L23-L32) publishes signaling on all interfaces. This is a development configuration, not proof of an exposed production deployment or that Redis currently stores sensitive data. Restrict host bindings and define authenticated, encrypted production networking before any shared deployment.

**RS-03 — Medium, confirmed static: gateway guard is narrower than its claims.** [Gateway:29–44](https://github.com/knarayanareddy/roomsmith/blob/7036277be3f81dad1c3dafa3cc29c2ce04cf9807/packages/model-gateway/src/index.ts#L29-L44) includes `" execute_command"` and `" puzzle_complete"`, but [lines 79–94](https://github.com/knarayanareddy/roomsmith/blob/7036277be3f81dad1c3dafa3cc29c2ce04cf9807/packages/model-gateway/src/index.ts#L79-L94) trim incoming keys before lookup; those entries cannot match their normal spellings. A direct gateway caller can therefore receive such output as `ok` if no other rule matches ([lines 172–199](https://github.com/knarayanareddy/roomsmith/blob/7036277be3f81dad1c3dafa3cc29c2ce04cf9807/packages/model-gateway/src/index.ts#L172-L199)). This is not evidence that a command executes or that the bounded director accepts it: its [output validator:228–257](https://github.com/knarayanareddy/roomsmith/blob/7036277be3f81dad1c3dafa3cc29c2ce04cf9807/services/director/src/director-service.ts#L228-L257) rejects extra fields and requires an authored variant. Fix and independently test the gateway boundary; do not use its booleans as proof of media isolation.

**RS-04 — Medium, unverified risk: timeout does not cancel provider work.** The gateway starts `this.provider!(request)` and races it against a timer ([gateway:160–173](https://github.com/knarayanareddy/roomsmith/blob/7036277be3f81dad1c3dafa3cc29c2ce04cf9807/packages/model-gateway/src/index.ts#L160-L173)); its [cleanup:200–215](https://github.com/knarayanareddy/roomsmith/blob/7036277be3f81dad1c3dafa3cc29c2ce04cf9807/packages/model-gateway/src/index.ts#L200-L215) clears only the timer. A real provider could continue consuming resources or transmitting after fallback; actual adapter behavior is unknown. Define cancellation and resource bounds before connecting a provider.

**RS-05 — Owner decision / historical CI: successful demo is not a release gate.** [CI:38–57](https://github.com/knarayanareddy/roomsmith/blob/7036277be3f81dad1c3dafa3cc29c2ce04cf9807/.github/workflows/ci.yml#L38-L57) specifies frozen install, lint, typecheck, unit, contract, security and build. The snapshot reports [CI success](https://github.com/knarayanareddy/roomsmith/actions/runs/40123403840) and [Pages success](https://github.com/knarayanareddy/roomsmith/actions/runs/40123403852) at the pinned SHA; logs, test counts and artifacts were not inspected. [Pages:41–49](https://github.com/knarayanareddy/roomsmith/blob/7036277be3f81dad1c3dafa3cc29c2ce04cf9807/.github/workflows/pages.yml#L41-L49) builds a "standalone split-screen GitHub Pages bundle", not a native release. Pick actual release criteria rather than interpreting these successes as device validation.

## Five-discipline assessment

1. **Correctness:** The [director:159–188](https://github.com/knarayanareddy/roomsmith/blob/7036277be3f81dad1c3dafa3cc29c2ce04cf9807/services/director/src/director-service.ts#L159-L188) bounds context and [director:266–298](https://github.com/knarayanareddy/roomsmith/blob/7036277be3f81dad1c3dafa3cc29c2ce04cf9807/services/director/src/director-service.ts#L266-L298) falls back on invalid gateway output. Engine ordering, persistence recovery and full transport integration are not verified. RS-03 and RS-04 need independent negative tests.
2. **Automation/testing:** Existing scripts and historical CI are valuable, not independently observed passes. The tree lists integration and E2E placeholders; this does not establish that other integration tests are absent. [README:22–24](https://github.com/knarayanareddy/roomsmith/blob/7036277be3f81dad1c3dafa3cc29c2ce04cf9807/README.md#L22-L24) describes intentionally unavailable integration/deployment targets and draft publication checks. Verify tests exercise real boundaries, not mirrored logic.
3. **DevOps/operations:** RS-02 blocks shared deployment. Compose uses mutable image tags and installs on container startup ([Compose:17–32](https://github.com/knarayanareddy/roomsmith/blob/7036277be3f81dad1c3dafa3cc29c2ce04cf9807/docker-compose.yml#L17-L32)); image provenance, deploy isolation, monitoring and restore are unverified. CI actions use version tags ([CI:17–34](https://github.com/knarayanareddy/roomsmith/blob/7036277be3f81dad1c3dafa3cc29c2ce04cf9807/.github/workflows/ci.yml#L17-L34)), not immutable commit pins.
4. **OWASP/security:** RS-01 is authorization, not merely CORS. [WebSocket upgrade:813–836](https://github.com/knarayanareddy/roomsmith/blob/7036277be3f81dad1c3dafa3cc29c2ce04cf9807/services/signaling/src/websocket-signaling-server.ts#L813-L836) does not check Origin in the inspected handler; cross-site reachability remains untested. Companion credentials are checked, not universally absent. Model prompt/injection protection and data egress require testing at actual provider boundaries (RS-03/04). The pairing audit stores redaction markers ([pairing:288–296](https://github.com/knarayanareddy/roomsmith/blob/7036277be3f81dad1c3dafa3cc29c2ce04cf9807/services/pairing/src/pairing-service.ts#L288-L296)), but demo log handling and credential retention still need review. A lockfile and frozen install exist; no independent vulnerability or supply-chain audit was run. Raw media, minors' data, retention and deletion require end-to-end verification, not inferred safety.
5. **UI/UX/accessibility:** A web simulator and companion test client exist; native apps do not. The content contract names `remote_fallback`, `no_timing_mode`, `color_independent_labels`, `reduced_motion`, and `captions` ([compiler:105–111](https://github.com/knarayanareddy/roomsmith/blob/7036277be3f81dad1c3dafa3cc29c2ce04cf9807/packages/content-compiler/src/index.ts#L105-L111)). Fields do not prove usable remote navigation, captions or accessible physical play. Validate with representative users and actual devices.

## Owner decisions and evidence limits

Choose intended deployment boundary, identity/credential issuer and session ownership, real provider/account and retention policy, target Fire OS/Android devices and signing, TURN/cloud provider, approved content reviewers, domain safety and accessibility testers, backup/recovery objectives and release authority. No certification is implied.

Inspected complete materialized sources: `README.md:1–47`, `package.json:1–39`, `.github/workflows/ci.yml:1–57`, `.github/workflows/pages.yml:1–60`, `docker-compose.yml:1–117`, both `apps/*/src/server.ts` and `index.ts`, `packages/model-gateway/src/index.ts:1–217`; first 220 lines only of `packages/content-compiler/src/index.ts` and `packages/perception/src/index.ts`. Four pinned read-only GitHub calls inspected director, signaling entry point, WebSocket server and targeted pairing excerpts. Engine, most compiler/perception implementations, transport internals, UI markup, tests, lockfile and Actions logs were not fully reviewed. No project execution or installation occurred.
